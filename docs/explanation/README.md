# Explanation

Explanation gives context and background — the "why" behind a design, the
tradeoffs considered, how pieces relate to the bigger picture. The reader
is studying, not working; there's no task to unblock.

**Rules for this folder**
- It's fine to take a position, discuss alternatives that were rejected,
  and argue for a choice — this is the one mode that's allowed to have
  opinions.
- Don't turn this into disguised reference (see `docs/reference/`) or a
  disguised tutorial (see `docs/tutorials/`) — if a reader needs to *do*
  something to follow along, it belongs in one of those instead.
- Good candidates: architecture decisions, "why we don't use X," design
  tradeoffs, background a new contributor needs before the reference docs
  make sense.

Full treatment of this mode: [diataxis.fr/explanation](https://diataxis.fr/explanation/)
